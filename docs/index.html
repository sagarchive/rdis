Decompiler

Android natives and odd CPUs, read as C.

JNI calls by name.

A native method reaches Java through a table of 229 function pointers. rdis maps every slot, so the double indirection reads as the call it is.

// before: *(int64_t *)(*(int64_t *)x19 + 0x30)(x19, …)
x19_1->FindClass("java/io/IOException")
// from libdatastore_shared_counter.so, arm64

// a RegisterNatives table entry becomes a header:
/* JNI native nativeInit(Ljava/lang/String;I)V */

Structs, recovered.

MIPS and RISC-V go through an IR built on Ghidra's P-code, or on rdis's own frontend when pypcode isn't installed. Field accesses through a pointer argument become a real struct, shared with the functions it's passed to.

struct s_10100_0 {
    int64_t f_0;   /* +0x0 */
    int64_t f_8;   /* +0x8 */
};

int64_t entry(struct s_10100_0 *a0) {
    return a0->f_0 + a0->f_8;
}
// RISC-V: ld, ld, add, ret

Where Hopper is still ahead: its decompiler is more mature. rdis lifts code by matching patterns, so heavily optimized code comes out rougher, vectorized SIMD lifts to comments, and struct recovery stops at field offsets.
